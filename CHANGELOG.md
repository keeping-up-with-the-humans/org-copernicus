# Changelog

## 0.1.0

First release. The detection coders were ported from a frozen research snapshot (manifest sha256 53d269895adae41edfce7f4df9c9a201f23eff00d6029a3eb5298e8c38a734df).

- **Rubric, data, LLM backends and coders.** Rubric model, JSON schema and loader with the id and marker-name rules, under which no attribute or marker id is `construct` or ends in `__rollup`, the names of the generated whole-construct and roll-up targets, and a rubric checks its ids and its marker names when it is constructed, with the loader's rules and messages, so one built in code obeys both rules too; literature sources are given for the rubric as a whole (required, possibly empty), for each attribute (optional, a missing list being an empty one) or both; validated text tables from CSV, parquet and JSON lines; OpenAI-compatible, vLLM and fake backends with JSON answer parsing and repair; the two-stage and one-stage LLM coders with the research's prompts, a resumable run store, shard merging, and tidy exports of scores, evidence and provenance. The run store records the text hash of every result, so a resumed run refuses texts that changed under their ids and a merge refuses stores that hold different texts under one id (it checks each source again against the target inside the transaction that copies it, on the snapshot it copies, so a store that changed after the first check is refused as well); it records what the backend applied, the temperature and `top_p` of the scoring calls per row and the temperature of the accepted extraction attempt per attribute (`stage1_temperature_applied`, also in `export_scores`), so the record matches the call after a retry; the failure check at the end of a run judges the requested texts and runs with the stored results included, so a rerun of a failed run fails again, while the checks after each batch judge the run's own calls, so a failing backend still stops early; `retry_failed` codes failed cells again; a store whose tables lack a column of this layout, or hold another, is refused by the runner, the merge and every export but the provenance, which compare every column with the ones that the store's rubric implies, as made by an earlier version of the library or changed by hand; and the provenance of an OpenAI-compatible backend records a digest of the endpoint's path without its trailing slashes, so two deployments on one host do not share a run identity.
- **Embeddings, references, similarity and hybrid coders.** Encoder registry and embedding sets with checkpointed, chunked encoding; generated reference texts for the poles of each construct and attribute, with a screen and a resumable generator; the similarity coder with its grid of settings; the hybrid coder over the verified passages of a two-stage run. A reference set records the content hash of the rubric it was written for, its files and the reference embeddings keep it, and every scoring path refuses references of another content of the rubric, also one edited under the same ids, before it scores; the provenance of a scoring run records the hash of the references and how the set came by it (`bound_with`, `generated` or `for_rubric`); a set written by hand is bound to a rubric with `ReferenceSet.for_rubric`; a set file without the hash is refused as written by an earlier version unless `ReferenceSet.load(path, bind_to=rubric)` binds it as the same explicit act, and reference embeddings without it are embedded again. The description of a reference set file names the content of its table (`table_hash`), and the sidecar of reference embeddings and of an embedding set the content of its arrays (`arrays_hash`): every load refuses a payload that its sidecar does not name, as a save stopped between its two writes leaves, and the generator's resume keeps the rows of the calls its description lists only after their digest matched; a file without the digest is an earlier version (bind a set with `ReferenceSet.load(path, bind_to=rubric)`, which accepts its table; embed again otherwise). A reference set holds its table in one canonical form, with the columns in their order, integers as int64, floats as float64, strings and a boolean screen flag (`copernicus.references.files.canonical_frame`), so a set built by hand in other dtypes saves and loads with its values and its digest, and a missing text or screen reason is refused when the set is built. The hybrid coder refuses, before anything is embedded, a text whose extraction failed for an attribute in the run, unless the text is short, instead of scoring it as a text without evidence; a failed scoring keeps its passages and is scored as usual.
- **Validity and baseline.** The validity panel with rank validity, score errors, reliability ceilings, noise, and group-clustered bootstrap intervals, and a plain-language report, which refuses a score frame whose attribute ids take the name of a generated target; the NLP-ML baseline with ridge regression on embeddings over seeds, training sizes and encoder sets, and its learning curves.
- **Corrections.** Human sampling of whole groups and sample-size planning, the planner in its own module `copernicus.corrections.planning`; cross-fitted predictions; pseudo-values; prediction-powered estimates of a mean, a group difference and regression coefficients; moment subtraction, SIMEX, instrumental-variable and repeated-study estimators; the battery that compares the corrections out of sample. A draw records the fingerprint of its table's texts and their groups (`population_hash`), and `attach_draw` refuses correction data with other texts or groups, renamed groups included, before it reads a human value, giving the counts of both tables and the drawn texts the data lack, and then a draw whose ids repeat or whose texts, groups, counts or inclusion probability do not describe its table; a draw without the fingerprint is refused as made by an earlier version. `CorrectionData.population_hash` holds the fingerprint of the data, computed once per object, and the repeated study and the battery's diagnostic draw with it instead of computing it again. `write_draw` and `read_draw`, which take a `str` or a `Path`, keep a draw in a JSON file, with the fields of `SampleDraw` as the one list both use; the description that `corrections sample` writes beside the drawn texts is such a draw file; and `read_draw` refuses a file of an earlier version (draw again) and one whose counts contradict its groups. `corrections estimate --draw` binds the coded sample to the texts file with the checks of `attach_draw`, takes `pi` from the draw and refuses a `pi` column of the gold file that differs from it; without `--draw` the command keeps `--pi-column` and the check of whole groups. The misclassification matrix's `fit` checks its training texts with the check of `applies`, the number of classes, the floor of texts per class and the informedness floor as the correction is configured, and raises `NotApplicableError` below them, also on the direct path after `applies` passed on a larger sample; latent pooling's `fit` refuses fewer than two score columns as its `applies` does; and every family's `fit` raises `NotApplicableError` with the reason of `applies` on a condition that `applies` reports, also supervised stacking's fewer than two score columns, the training texts from fewer than two groups of stacking and embedding-augmented calibration, the missing embeddings of the latter and the gold of `platt` that does not take two values. `draw_groups` computes the fingerprint of the arrays it draws from, and `draw_from_data` draws the data's own texts with the data's fingerprint.
- **Command line.** The `copernicus` command with the groups `rubric`, `code`, `store`, `references`, `embed`, `similarity`, `hybrid`, `validity`, `baseline` and `corrections`. The help tests run the same on a hosting service's runner, which forces Typer's terminal rendering, as locally.
- **Packaging.** Typed package (`py.typed`), MIT license, toy rubric, corpus and cue words for the examples and tests. The distribution is named `org-copernicus` on the package index, while the import name and the command are `copernicus`.
- **Remote code.** The one registered encoder that runs the model repository's own code is pinned to a commit; a specification or backend that allows remote code without a pinned commit, the full 40-character hash, is refused.
- **vLLM provenance.** The provenance of the vLLM backend records the engine options as canonical JSON of their values (a number stays a number, a nested option stays nested), and the backend refuses an option that is not a JSON value; the provenance, and so the run identity, changes for a run with engine options, so a store coded with engine options before this change does not match a resume after it.
- **Documentation site.** The `docs` workflow builds the site strictly (`mkdocs build --strict` on Python 3.12 with the `docs` extra) and deploys it through GitHub Pages on every push to `main` of the public repository.
