# Changelog

## 0.3.0

### Upgrading from 0.2.0

What changes for a user of 0.2.0, in short. Each point names the entry below that describes it in full.

Tables that gain a column:

- `repeated_study` returns the columns `n_rank_deficient_folds` and `n_se_exactly_zero` after `status`, as the last two of its columns (`copernicus.corrections.study.RESULT_COLUMNS`), so code that compares the whole list of columns, or that reads a column by its position after `status`, sees two more columns. The two columns are appended, and the records leave every other column as it was; the rows of `calibrated` can change through the refusal of a calibration line listed below (see **Values that stand in for a quantity the data do not identify**).

Calls that now stop with a reason:

- An embedding pass (`Encoder.embed`, `Encoder.embed_table`, `copernicus embed texts`, the embedding of reference texts and the hybrid coder) stops with `ConfigurationError` for a text one of whose windows the tokenizer turns into no token, and for a window or a text whose vector is shorter than `1e-12`. Version 0.2.0 could return vectors in both cases: for a text with an empty window a vector of the text that did not depend on that window, and a vector shorter than `1e-12` unscaled. Embedding such a text again now stops (see **The encoder refuses a window without a token and a vector without length**).
- `mean_pool`, `cls_pool` and `last_token_pool` of `copernicus.embeddings.pooling` stop with `ConfigurationError` for a batch with a row whose attention mask is all zero. For such a row 0.2.0 returned a zero row from `mean_pool` (for finite token vectors) and, in a batch with a token position, the model's output at a padding position from the other two (same entry).
- An embedding pass stops with `ConfigurationError` for a window or a text whose vector has a computed length that is not finite; 0.2.0 returned a vector of NaN, or of zeros where the sum of the squares overflowed (see **A calibration line of numerical rank 1 and a vector whose length is not finite are refused**).
- `fit_ols_line`, and with it the `linear` calibration, the calibrated pseudo-values and the `calibrated` estimator of `repeated_study` (which counts such a draw as undefined), stops with `EstimatorError` for a score on which the design of intercept and score loses its numerical rank: values that are very large beside 1, or that vary very little beside their mean. Version 0.2.0 returned the coefficients of smallest norm, which need not be the least-squares line (same entry).
- `construct_scores` of `copernicus.coders` stops with `ConfigurationError` for a finite attribute score whose absolute value is above `copernicus.coders.MAX_ABSOLUTE_VALUE` (`1e150`), and `validity_panel` and `copernicus validity panel`, under both units, for such a score, gold value or covariate. The value is compared as a 64-bit float, and a finite number too large for a finite float is above the limit; the message names the kind of value, the texts, the largest absolute value and the remedy, to divide the column by one constant. Version 0.2.0 averaged such values, and a sum that overflowed could leave a construct score or a correlation missing, or make the panel take a text's other runs for the text and report a wrong correlation without a warning (see **A limit on the size of scores, gold values and covariates**).
- `ols_outcome_ppi`, `ols_predictor_ppi` and `copernicus corrections estimate` stop with `ConfigurationError` for a formula that uses, inside a stateful transform such as `center()`, a name of the library's own code, as `center(pd.Series(x))` does. Version 0.2.0 evaluated such a formula (see **A formula no longer sees the library's own variables**).
- `ols_outcome_ppi`, `ols_predictor_ppi` and `copernicus corrections estimate` stop with `ConfigurationError` for a formula whose design holds a value that is no real number and that 0.2.0 evaluated all the same: a text that reads as a number, such as `'1.5'`, in a text column of the `string` type of pandas, in an Arrow column of strings or of bytes, or in a text constant (`I("1.5")`), which numpy turned into a number although the same texts in a text column of another type are coded by their levels; a complex number, of which numpy kept the real part under its `ComplexWarning`; and a number of another package that is not registered as a real number of Python, such as a symbolic expression, which numpy turned into a float. Turn such a column into floats before the call, or code a text column by its levels with `C()` (see **Errors of a formula that are now the library's own**).
- The same functions raise the library's own errors where 0.2.0 passed on an error of `formulaic`, Python or numpy, so code that caught the earlier class must catch the new one: `SettingsError` for a formula that cannot be parsed (0.2.0: `FormulaSyntaxError` or `FormulaParsingError` of `formulaic`, or Python's `SyntaxError`) and for a formula of several parts (0.2.0: `AttributeError`); `ConfigurationError` for a formula over a column of dates or of durations, or over a column of decimal objects inside a transform such as `center()` (0.2.0: `TypeError`), for a design with a text that does not read as a number or with a list, and for a name that `formulaic` reports as read by the formula and that two columns of the data have (0.2.0: `ValueError`), and for contrasts of the wrong form (0.2.0: `IndexError`) (same entry).

A call that no longer stops:

- `ols_outcome_ppi`, `ols_predictor_ppi` and `copernicus corrections estimate` evaluate a formula that fills a missing value itself outside a transform, such as `x.fillna(0)`, and a formula that turns a missing value into a value, such as `I(x > 0)` on a column of floats, where the comparison is false for NaN. Version 0.2.0 refused both because the formula read a column with a missing value (see **A formula no longer sees the library's own variables**).

The lowest version of a dependency:

- `formulaic` must be 1.2.2 or later; 0.2.0 declared 1.0. Under `formulaic` 1.0 no formula of the OLS estimators could be evaluated, under 1.1.0 to 1.2.0 with pandas 3 a formula with a text column failed, and under 1.1.0 to 1.2.1 a formula with a quoted name that holds a space failed (see **A formula no longer sees the library's own variables**).

Numbers that change from 0 to missing:

- `mean_words_evidence` in the summaries of `evidence_texts` and `score_hybrid` is NaN when no text uses its passages, and `share_screened_out` of `screen_report` is NaN for an empty table; 0.2.0 gave 0.0 for both. `copernicus hybrid score` writes such a mean as `null` in its description file and, at construct granularity, prints `none` (see **Two means of nothing are missing, not 0**).

Numbers read from a CSV file under a pandas before 3.1:

- `read_frame`, `TextTable.read` and the commands that read texts, scores, gold values or coder scores from a CSV file ask a pandas before 3.1 (pandas 2 is what Python 3.10 installs) for its exact parser of floats. A value that such a pandas reads as a float can therefore change in its last digits against 0.2.0. At the edges of the floats more can change there: a negative number that underflows is read as `-0.0`, and a number at or beyond the largest float can make a column numeric that pandas 2 left as text. Under pandas 3.1 or later nothing changes (see **Floats of a CSV file are read exactly under every pandas version**).

Vectors that change:

- With `cls` pooling and `padding_side="left"`, a window shorter than the longest window of its batch gets the vector of its first attended token, where 0.2.0 took the model's output at a padding position; this can change the stored vector of the window and the vector of its text. A checkpoint of such a pass that 0.2.0 wrote is refused, not resumed. With padding on the right, the side of the registry's `cls` encoder, a pass that returns vectors in both versions returns the same vectors (see **`cls` pooling reads the first token on either padding side**).

### Changes since 0.2.0

- **The fewest defined bootstrap resamples.** `moment_subtraction`, `simex` and `oriv` take `min_defined`, the fewest bootstrap resamples with a defined estimate from which the standard error is computed (default 50, an integer from 2 to `n_boot`, and `n_boot` must be at least `min_defined`), and `below_floor`, what happens with fewer: `"refuse"`, the default, raises `EstimatorError` with a message that names the floor, and `"point"` returns the point with `se`, `ci_low` and `ci_high` as NaN and logs one warning that names the counts. The details of every estimate of the three add `min_defined`, `below_floor` and `se_status` (`ok`, or `too_few_defined` when the standard error was left out) after `n_boot_defined`, and `copernicus corrections estimate` takes `--min-defined` and `--below-floor` for the kinds `moment-subtraction`, `simex` and `oriv`, writes a missing standard error and interval as null, and prints `none` for the interval. Version 0.2.0 refused every estimate of the three with fewer than 50 defined resamples, and every `n_boot` below 50. The new arguments leave the default bootstrap settings, draws and calculation unchanged; the other entries below describe the further records and warnings. The arguments `min_defined=10` and `below_floor="point"` take the floor of the paper's analysis code and keep the point as that code did, for a point that is defined; which resamples count as defined, and the refusal of an undefined point, stay the library's own.
- **A warning for whole-group draws from groups of unequal size.** `copernicus.corrections.text_count_variation(group_id, m)` returns `c`, the coefficient of variation of the number of texts of a draw over all draws of `m` of the `G` groups, `(sd_n / mean_n) * sqrt((1 - m / G) / m)` with `n_g` the number of texts of group `g`, `mean_n` their mean and `sd_n` their standard deviation with divisor `G - 1`. For a mean over the drawn texts of a quantity fixed before the draw, such as the point of `mean_ppi` without power tuning and with a score as its prediction, the bias is at most `c` times the standard deviation, both taken over all possible draws, provided the estimator refuses no draw; `c` does not bound a difference, a power-tuned or cross-fitted estimate, a summary over the accepted draws only or any coverage. `TEXT_COUNT_VARIATION_THRESHOLD` is 0.1, and the warning is decided on the square of `c` computed exactly from the counts. `draw_human_sample`, and with it `copernicus corrections sample`, logs one warning when `c` exceeds 0.1, which names `c`, `m`, `G` and the share of the texts that the largest group holds and says what to do; `repeated_study` logs one more warning for each size above the threshold, before the draws of that size, and `run_battery` one for each such size of its diagnostic, before its seeds; `c` counts texts, also when the quota counts another unit. Version 0.2.0 described the possible ratio bias in its pages and docstrings and did not warn about the variation of the number of drawn texts; its warning for a quota above half of the units is unchanged. This check changes no draw and no calculation; a draw, a study or a battery on groups of unequal size can log more warnings. The other entries below describe the new records, the study's new columns and the refusals.
- **Folds and draws of your own for the baseline.** `run_ridge_baseline` takes `splits`, a `copernicus.baseline.BaselineSplits` of two tables: `folds`, the test fold of every analysis text for every seed (columns `seed`, `text_id`, `fold`), and `draws`, the texts of each fold's training draw at each size (columns `seed`, `size`, `fold`, `text_id`, with `size` as the results table writes it), or `None`, and then the draws come from the keyed generators on the supplied folds. Before any fit it checks a copy of the splits, so that a table changed after construction meets the same checks, and refuses with `ConfigurationError`, naming the seed, the size and the fold where they apply and the first ten offending ids, folds whose seeds are not those of the settings, that hold a label outside `0` to `k_folds - 1` or an empty fold, miss an analysis text, hold one twice or hold another text, or put a group in two folds, and draws that the settings do not ask for or that, for a seed and size whose draws the run consults, miss a fold, reach outside the fold's training pool, hold part of a group, hold fewer units than the size names while the pool holds more, or are not the whole pool at size `"full"`. The skip reasons and the draw receipts follow the supplied splits; supplied draws of a size skipped for its quota or its pool are not used, with a warning, and a count size without any supplied draw whose smallest pool lies below the floor is skipped as `below_floor(<floor>):min_pool_units=<units>`. `BaselineResult` gains `splits`, the folds and every draw that the run consulted, those of a size then skipped below the floor included; seeds of any size and integer text ids, unsigned ones above the signed 64-bit range included, are kept exactly. `write_splits` and `read_splits` keep splits in a JSON file, as the draw file of the human sample keeps a draw, and an empty table comes back with the types of its columns; `copernicus baseline ridge` takes `--splits` and `--write-splits`, lists the written file among its outputs, and its description records the file it read, whether folds and a draws table were supplied (`supplied_splits`) and the file it wrote (`written_splits`). Version 0.2.0 drew the folds and draws only from generators keyed by the seed and the name of the gold column. With `splits=None`, the default, the generators of the folds and the draws, the skip rules and the fits are unchanged; the repair of the seed columns is described below, and the description of the command adds the keys `supplied_splits` and `written_splits`; a run given `result.splits` of an earlier run on the same inputs and settings gets that run's folds, draws and skips, also under another name of the gold column. Code that builds a `BaselineResult` itself passes `splits` too.
- **Values that stand in for a quantity the data do not identify.** Where a correction meets one of seven such cases, it returns the value that 0.2.0 returned and now records that the case occurred, with one warning per call of the function that meets it, logged under that function's module. Inside `run_battery` and `repeated_study` these warnings are counted instead: after its seeds the battery logs one warning for each entry and size whose fits or combinations met such cases, and after the draws of a size the study logs one for that size, each with the count of each case, a cross-fit of a draw counted once for both of its estimands; a battery or a study that stops with an error logs these warnings for the calls it finished, and every other warning is logged as before. `pseudo_values` with the `crossfit` rectifier holds `n_rank_deficient_folds`, the inner folds whose design `[1, score, covariate]` has a numerical rank below 3 on their labelled training rows, as `numpy.linalg.lstsq` with `rcond=None` returns it, which leaves out the directions below its cutoff and returns the coefficients of smallest norm of what remains (for a design that is rank-deficient in exact arithmetic, one of the many lines that fit the rows equally well) (0 when there is none, and for `identity` and `calibrated`); `repeated_study` counts the same folds for `ppi_crossfit` over a row's defined draws in its new column `n_rank_deficient_folds` (0 for the other estimators). The provenance of `multiple_imputation` holds `n_rank_deficient_resamples`, the bootstrap resamples whose design has a numerical rank below 3 in the same sense, and `n_resamples_without_residual_df`, the resamples of no more rows than the three coefficients, whose residual variance is the residual sum of squares divided by 1. The provenance of `latent_pooling` and of the `factor` combiner of `CorrectionEnsemble` holds `orientation_identified` (false when the row mean of the standardised score columns, or of the standardised members, is constant, so that the sign is the one numpy's decomposition gave, and when the computed correlation of the factor or the combined column with that mean is at most `1e-12` in absolute value, which the library treats as too small to identify the sign, as for two columns or members of unit variance that correlate negatively; the sign follows the computed correlation as before), `direction_unique` (false when in some round of the principal-axis iteration the two largest eigenvalues of the reduced matrix are equal up to a relative `1e-12`: the largest minus the second at most `1e-12` times the largest), `factor_converged` (false when the iteration reached its 50 rounds without meeting its tolerance, whose last loadings are kept; an iteration that meets it in its last allowed round has converged) and `n_factor_rounds`; the `pc1` combiner holds `orientation_identified` and `direction_unique`, by the same rule on the two largest singular values. The details of every estimate end with `se_exactly_zero`, true when the standard error is exactly 0, so that the interval has zero width; `moment_subtraction`, `simex` and `oriv` keep `se_status` beside it, which is `ok` whenever `se_exactly_zero` is true. The records of latent pooling, multiple imputation and the two combiners reach the provenance of every scored fold in the battery's results, and `se_exactly_zero` reaches the file of `copernicus corrections estimate`. The same record stands wherever else the library returns a standard error: `repeated_study` counts in its new column `n_se_exactly_zero` the defined draws of a row whose standard error is exactly 0, for each of its four estimators, and its warning for a size counts them; the result of `rubin_pool` holds `se_exactly_zero` and one warning says so when it is true; the stacked two-stage fit behind `oriv` holds it for its sandwich, which the details of `oriv` give as `sandwich_se_exactly_zero`. Version 0.2.0 returned the same values without these records or warnings. For a user of 0.2.0 the estimates of these cases are unchanged; the fields and keys are added, `repeated_study` returns two more columns, and a fit, an estimate, a study or a battery that meets one of the cases logs more warnings.
- **The encoder refuses a window without a token and a vector without length.** An embedding pass (`Encoder.embed`, and through it `Encoder.embed_table`, `copernicus embed texts`, `copernicus.similarity.embed_references` and the hybrid coder) stops with `ConfigurationError` in three cases. It stops when the tokenizer turns a window of a text into no token, under every pooling, before the model runs on that window's batch, and for the windows of a checkpoint before the first batch. It stops when the pooled vector of a window is shorter than `1e-12`, and when the vector of a text is. Each message counts the texts concerned and names the first ten by their ids; the hybrid coder at attribute granularity names a text as `<text_id> (<attribute_id>)`, and `embed_references` names a reference text by its position among the kept texts of the set, counted from 0. The pooling functions `mean_pool`, `cls_pool` and `last_token_pool` of `copernicus.embeddings.pooling` refuse a batch with a row whose attention mask is all zero and name the positions of the first ten such rows. Version 0.2.0 failed with an `IndexError` under `cls` and `last_token` pooling when all the windows of a batch were empty, and otherwise stopped with `ConfigurationError` for a text none of whose windows had a token. Where the pooling did not fail, 0.2.0 embedded a text with an empty window and a window with a token: the empty window got the weight 0, so a finite vector of that window added nothing to the weighted sum behind the vector of its text; the vector stored for the window was zero under mean pooling when the model's outputs for it were finite and, under `cls` and `last_token` pooling, the model's output at a padding position divided by its computed length, a length below `1e-12` being replaced by 1; and in a left-padded batch with such a window `last_token_pool` read every other row at its token count minus 1 in place of its last position, which can change the vectors of other texts. A vector shorter than `1e-12` was left unscaled. Embedding a text with an empty window again now stops, also where 0.2.0 returned a vector of the text that did not depend on that window. For a user of 0.2.0 a pass that returns vectors in both versions returns the same vectors, except under `cls` pooling with left padding (the next entry).
- **`cls` pooling reads the first token on either padding side.** `cls_pool` of `copernicus.embeddings.pooling`, and with it an embedding pass of an encoder with `cls` pooling, takes the vector of the first attended token of every row. Version 0.2.0 took the vector at position 0. In a batch padded on the left that is a padding position for every row shorter than the longest: the raw vector of such a window was the model's output there, its stored vector that output divided by its computed length (a length below `1e-12` being replaced by 1), and the vector of its text used the raw vector with the window's token count as its weight. In a batch padded on the right the first attended token is at position 0, so a pass that returns vectors in both versions returns the same vectors, bit for bit; `bge_m3`, the registry's encoder with `cls` pooling, pads on the right. The fingerprint of a checkpoint of a pass with `cls` pooling and left padding now holds a mark of the pooling rule, so a checkpoint of such a pass that 0.2.0 wrote is refused with `ConfigurationError`, not resumed: delete it and embed again. A checkpoint that holds a token count that is not finite or is negative is refused as well.
- **A calibration line of numerical rank 1 and a vector whose length is not finite are refused.** The least-squares line of the gold values on a score (`fit_ols_line`, which the `linear` calibration, the calibrated pseudo-values, the `calibrated` estimator of `repeated_study`, the anchor of latent pooling, the embedding-augmented calibration and `blind_transport` fit) stops with `EstimatorError` when the design of intercept and score has a numerical rank below 2 although the score varies, as `numpy.linalg.lstsq` with `rcond=None` returns it for the two columns as they are: a score whose values are very large beside 1, such as a standard deviation of 1e16 around 0, or vary very little beside their mean, such as a mean of 1e8 with a standard deviation of 1. Version 0.2.0 returned the coefficients of smallest norm for such a design, which need not be the least-squares line: for scores of mean 1e8 and standard deviation 1 whose least-squares slope is 1.97, a slope of 1e-8 on a line that nearly passes through the origin. Centre such a score and rescale it to a spread near 1. A design of rank 2 is fitted as before, by the same call; the rank does not certify the accuracy of a line fitted to values that are very large beside their spread. An embedding pass stops with `ConfigurationError` when the length of a window's pooled vector or of a text's vector is not finite: the vector holds a value that is NaN or infinite, or the sum of its squares overflows, in the model's output or in the weighted sum over the windows of a text; the message names the texts. Version 0.2.0 returned such vectors as NaN, and as zeros where the sum of the squares overflowed. For a user of 0.2.0 every line on a design of numerical rank 2 is as before, and so is every vector of a pass that returns vectors in both versions, except under `cls` pooling with left padding.
- **The `pca` reduction warns where a matrix leaves its sign or its direction open.** The first principal component that `reduce_matrix` and the similarity coder take with `pca` has a sign that follows its correlation with the row means of the matrix. The reduction now logs a warning where it treats the sign or the direction as open. When the computed standard deviation of the row means is 0, one warning says that the scores keep the sign of the decomposition. Otherwise, when the computed standard deviation of the scores is positive, one warning is logged when the computed correlation of the scores with the row means is at most `1e-12` in absolute value, as for two columns of unit variance that correlate negatively, whose component is their difference, and one when the range of the row means is at most `1e-12` times the larger of 1 and their largest absolute value. Whatever the row means, one warning is logged when the two largest singular values of the centred standardised matrix differ by at most a relative `1e-12`. The thresholds are conventions on computed numbers: a value below one can be genuine. Every score that the reduction returns is as computed and is the one that 0.2.0 returned. The check of the singular values is a decomposition of its own, `numpy.linalg.svd` without the vectors on the standardised matrix, read as 64-bit floats, minus its column means, because the eigenvalues of a Gram matrix square the entries, which hides a tie in 32-bit floats and makes one where the squares underflow. Should that decomposition not converge, the reduction stops with `ConfigurationError` and returns no scores.
- **Two means of nothing are missing, not 0.** `mean_words_evidence`, the mean number of words of the evidence texts in the summaries of `copernicus.hybrid.evidence_texts` and `score_hybrid`, is NaN when no text uses its passages (at attribute granularity for each attribute without such a text), and `share_screened_out` of `copernicus.references.screen_report` is NaN for an empty table. Version 0.2.0 gave 0.0 for both, a number that a table with texts can also have. The counts beside them are unchanged. Test such a mean with `math.isnan`: a NaN does not equal itself. `copernicus hybrid score` writes such a mean as `null` in its description file, where it makes the summary strict JSON; at construct granularity it prints `none` in its summary, and at attribute granularity it prints no mean, the description file holding one for each attribute. For a user of 0.2.0 every other value is as before.
- **The rule behind a value is stated where you read about it.** The docstrings and the methods pages now state rules that the code followed without saying so: that the communalities of the principal-axis iteration are kept between `1e-6` and 1 after every round while its loadings are not bounded, so an improper solution returns a loading above 1 in absolute value; that SIMEX treats a curve as flat when its range is at most `1e-9` times its largest absolute value, and that the status `linear_limit` returns the value of the fitted rational curve at a pole between the last grid point below the cap and the cap, which with the multiples and the cap of `simex` is close to the straight-line extrapolation and not equal to it (the page had said that it gives the straight-line extrapolation); that the first-stage statistic of `oriv` is infinite when the squared correlation of the two proxies is 1 or more; that the error variance of the Tweedie proxy can be negative only by rounding and is then set to 0, and that the Tweedie map gives a score outside the training range the value at the nearer end; that the `quantile` map gives a score beyond the training scores the smallest or largest training gold value, or the median of the `t` smallest or largest when `t` training texts share the score at that end; that `platt` fits scikit-learn's logistic regression with an L2 penalty on the slope at `C = 1`, which the code now passes by name; that a ridge path with no singular direction left after its cutoff predicts the mean of the target, and that the baseline's ridge drops the eigenvalues of the centred design's Gram matrix at or below `1e-10` times the larger of the largest eigenvalue and `1e-300`, and refuses a design with none left; that `pmm` with fewer training rows than `k_donors` draws from every training row; that the `pca` reduction keeps the sign of the decomposition when the row means do not vary, and that a column that does not vary adds nothing to the component beyond rounding; that `replicate_noise` on the observed scale gives 0 for scores that are constant by the library's rule for a constant series, also when they differ within its tolerance; and that the stacker gives an exactly constant feature the coefficient 0, while a feature that varies within that tolerance keeps its variation. Two missing values now carry their reason: the details of `oriv` hold `shared_error_correlation_status` (`ok`, or `constant_residual` when the residual of a proxy on the gold values is constant on the labelled texts, so that `shared_error_correlation` is NaN), and the provenance of a `multiple_imputation` fit holds `between_variance_status` (`ok`, or `single_draw` when one draw leaves no variance across draws, so that `between_variance` is NaN). For a user of 0.2.0 every value is as before, with these two keys added.
- **Seeds of the signed and the unsigned 64-bit type in one baseline run.** When the signed and the unsigned 64-bit seed columns of the out-of-fold tables were joined into one column of floats, which do not hold every 64-bit integer, as with the Python-integer seeds `(42, 2**63)`, a run of `run_ridge_baseline` at the size `full` failed with an error such as `ValueError: '42.0' is not in list`. A join that gives floats is now rebuilt from the integer seeds, in the function and in `copernicus baseline ridge`. For Python-integer seeds that all lie between `-2**63` and `2**64 - 1`, some below and some at or above `2**63`, the rebuilt column is unsigned if no seed is negative and holds Python integers otherwise. A run whose seed columns join to an integer column or to a column of Python integers keeps that column, as in 0.2.0. `copernicus baseline ridge` with `--out` a parquet file refuses, before any fit, seeds that fit no single 64-bit integer type (all from `-2**63` to `2**63 - 1`, or all from 0 to `2**64 - 1`), because a parquet file has no integer column for them, and names the `.csv` output, which keeps every digit; in 0.2.0 such a run with a seed beyond 64 bits ended in an `OverflowError` of the parquet writer after the fits.
- **A limit on the size of scores, gold values and covariates.** `copernicus.coders.MAX_ABSOLUTE_VALUE` is `1e150`. `construct_scores` refuses a finite attribute score above it in absolute value with `ConfigurationError`, after its check of run numbers and before it averages; a value of another numeric type, such as a Python integer in an object column, is read as a float for the check, and a finite number without a finite float, such as a decimal of `1e400`, is above the limit. `validity_panel`, and with it `copernicus validity panel`, refuses under either unit a finite score above the limit in the rows a target is built from (every attribute row for the construct), before those rows are averaged and also for a text without a gold value, and, before any metric is computed, a finite value above it anywhere in a gold column that a target names or in the covariate column; the items of `PanelSettings.items` are not covered. The message names the target of a score or the column of a gold value or a covariate, the first ten texts, the largest absolute value as a float (or that it is beyond the range of 64-bit floats), the limit and the remedy, to divide the column by one constant before the call. A value up to the limit can be squared in 64-bit floats and a sum of such values is finite, so no mean of the panel's inputs overflows; a sum of squares of very many values close to the limit can still overflow in a metric, with numpy's warning as the notice. In 0.2.0 a sum that overflowed could make the construct score of a run missing, so that the panel took the text's other runs for the text: twelve made-up texts with two runs, one of which held `1e308` on all three attributes in its first run, gave a Spearman correlation of 1.0 with status `ok` and no warning, where the value on the scores as given is 0.5385. Missing values and infinities keep their rules, and a call whose values all lie within the limit returns what it returned, with one exception: attribute scores in a column of floats narrower than 64 bits whose mean overflowed in that width (two scores of `3e38` in a 32-bit column) now have the mean of their 64-bit values, where `construct_scores` returned an infinite or a missing construct score; a group with an infinite score keeps the mean it had. `resolve_target_scores` refuses a score above the limit only for the generated construct of a long attribute table, under either spelling of its key, through `construct_scores`.
- **Validity panel: averages of finite values that overflow.** Finite values can have an average that is not finite, because adding them overflows the range of 64-bit floats: two scores of `1e308` have no finite sum. `validity_panel` refuses such values before it averages anything (see **A limit on the size of scores, gold values and covariates**). `compute_target` of `copernicus.validity.panel_targets` and the reductions of `copernicus.validity.panel_units`, called directly with larger values, report such an average themselves. Under `unit="group"` they stop with `ConfigurationError` for a group whose mean score or mean covariate over its texts is not finite although the value of every text is, naming the target and the group, and for a group whose mean score in a run of its noise is not finite, naming the run as well; the errors name the remedy, to divide every score (or every covariate) by one constant. Version 0.2.0 went on with these three means. The group unit's refusal of a text whose run-averaged score is not finite names finite run scores whose average overflows among its causes, and the remedy. Under `unit="text"` such a text is dropped and counted as before, with one warning per target that names the texts with a gold value that are dropped for this reason. These averages are computed with numpy's warnings of an overflow and of an invalid value turned off. Called directly with finite scores near the largest float, these functions can still leave a metric or the noise missing, with numpy's warning as the only notice.
- **Floats of a CSV file are read exactly under every pandas version.** The CSV parser of a pandas before 3.1 does not round every number correctly by default: it can read a float that pandas itself wrote with all its digits back as a neighbouring float, where pandas 3.1.0 reads every one back to the same bits. `read_frame` of `copernicus.data`, and with it `TextTable.read` and the commands that read texts, scores, gold values or coder scores from a CSV file, used that default. The reader now asks a pandas before 3.1 for its exact parser (`float_precision="round_trip"`); from 3.1 on the default parser is exact, and pandas warns that the option is deprecated. Where pandas reads a column as floats, each float is then the one nearest to its text. Which columns pandas reads as numbers, and which of its missing-value strings it finds in them, stays its own inference and can still differ between its versions: pandas 2.3.3 leaves a column with `99999999999999999999e-19` as text, and pandas 3 reads 10.0. Under a pandas before 3.1 a value read from a CSV file can differ from the one that 0.2.0 read, mostly in its last digits. The option also changes what those versions read at the edges of the floats: the text `1.7976931348623158e308`, which lies just above the largest float and rounds to it, is read as that float, where pandas 2 left the column as text and pandas 3.0 read infinity; a negative number that underflows is read as `-0.0`, not `0.0`; and a number beyond the largest float can make a column numeric that pandas 2 left as text, by the sign and the platform (on Linux `-1e309` is read as `-inf` and a column with `1e309` stays text; on macOS `1e309` is read as infinity). Parquet and JSON-lines files, and CSV files under pandas 3.1 or later, are read as before. The reader stops with `ConfigurationError` when the version of the installed pandas cannot be read. The files of a reference set read their floats exactly on every version already.
- **A formula no longer sees the library's own variables.** `formulaic` hands a formula the variables of the function that asks for its design, and 0.2.0 did not prevent that. Before a formula is evaluated, the library asks `formulaic` which columns it reads and refuses a name that is no column of the data, so `pd.Series(x)` was refused, as a Python builtin outside a stateful transform is (`abs(x)`). But `formulaic` 1.2.2 reports no name inside a stateful transform such as `scale()` or `center()`, so `center(pd.Series(x))` was evaluated with the library's own `pd`, and through the library's own variable for the data a formula could read a column past the check of its columns. The OLS estimators (`ols_outcome_ppi`, the covariates of `ols_predictor_ppi`, and `copernicus corrections estimate` with `--formula` or `--covariates`) now evaluate a formula with the columns of the data, the names that `formulaic` provides (its transforms and `np`) and Python's builtins; another name is refused with `ConfigurationError`. A formula is now judged by its design. Version 0.2.0 refused a formula that `formulaic` reported as reading a column with a missing value, also when the formula filled the values itself, as `x.fillna(0)` does, while `center(x.fillna(0))` was evaluated, because the report of `formulaic` 1.2.2 names no column inside a stateful transform. Both are evaluated now, and a missing value that reaches the design is refused as before. A formula that turns a missing value into a value without a fill is evaluated too: `I(x > 0)` is false where a column of floats holds NaN, so whoever needs every input observed checks the columns before the call. In a column of a nullable type of pandas the comparison stays missing and the design is refused; `I(x.fillna(0) > 0)` fills it. A numpy masked array inside a formula is read by its data, and its mask is no missing value of the design. The declared lowest version of `formulaic` rises from 1.0 to 1.2.2: under 1.0.0, 1.0.1 and 1.0.2 the report does not exist and every formula failed with `AttributeError`; under 1.1.0, 1.1.1 and 1.2.0 with pandas 3.1 a formula with a text column failed with `ValueError`; and under 1.1.0 to 1.2.1 the report failed with `SyntaxError` on a quoted name that holds a space and on a quoted name inside a transform. Among formulas that returned an estimate in 0.2.0, this change alters an estimate only for a formula that depended on the names taken out of its reach: one that used such a name inside a stateful transform, or one that counts or lists the names within its reach, as `len(locals())` does.
- **Errors of a formula that are now the library's own.** The docstrings of `ols_outcome_ppi` and `ols_predictor_ppi` promise `SettingsError` for a malformed formula and `ConfigurationError` for a design that does not match the data, and 0.2.0 kept the promise only in part. A formula that `formulaic` cannot parse left the functions with the error of `formulaic` (`FormulaSyntaxError`, `FormulaParsingError`) or with Python's `SyntaxError`, and `copernicus corrections estimate` showed a traceback for a mistyped `--formula`; a formula of several parts separated by `|` ended in an `AttributeError`; a column of dates or of durations ended in a `TypeError` of numpy, as did a column of decimal objects inside a transform such as `center()`; contrasts of the wrong form ended in an `IndexError` of `formulaic`; a name that `formulaic` reports as read by the formula and that two columns of the data have ended in a `ValueError` of pandas; and a design with a text, which `formulaic` 1.2.2 passes on for a text column of the `string` type of pandas, for an Arrow column of strings or of bytes and for a text constant, ended in numpy's `ValueError`, unless the text reads as a number, in which case it was taken as a number without a word. A design of complex numbers lost its imaginary part under numpy's `ComplexWarning`. Now a formula that cannot be parsed is refused with `SettingsError`, whose message holds the first line of the parser's message, and so is a formula of several parts, before anything is evaluated. `ConfigurationError` is raised for a reported name that two columns have; for an evaluation that fails with a `TypeError` or an `IndexError`, as before for the `FactorEvaluationError` of `formulaic` and a `ValueError`; and for a design column with a value that does not count as a real number, which the message names with the type of that value. The real numbers of Python and of numpy, fractions and decimals, such as those of an Arrow column, count and are turned into floats as before; a text, a complex number, a duration, a list and a number of another package that is not registered as a real number of Python do not. The error of `formulaic`, Python or numpy is kept as the cause where there is one; an evaluation that fails with an `ArithmeticError`, and a last conversion of the finished design into floats that fails with one, as for a number too large for a float or a decimal that signals an invalid operation, are refused with `ConfigurationError` too (0.2.0: Python's `OverflowError` or `FloatingPointError`, and `decimal.InvalidOperation`), and another error that `formulaic` raises while it builds a design is passed on as it is. This change alters no estimate of a formula whose design holds only real numbers of Python or of numpy, fractions and decimals.

### Changes since 0.1.0

- **Validity panel, one score per group.** `PanelSettings(unit="group")` and `copernicus validity panel --unit group` compare one score per group with the group's gold value, for a gold value that belongs to a group of texts such as a person who wrote several of them. A group's score is the mean over its texts that were scored for the target, each text's runs averaged first; a text never scored for the target does not enter, and `n_texts` counts the texts that did. The metrics and intervals are computed on the group rows, each group its own cluster of the bootstrap, and the noise on each group's mean score in the runs that all its texts have a score for. The setting needs a table with a group column whose ids neither merge nor split when written as text; a group that holds a text scored for the target with a finite gold value stops the panel when its texts with a gold value carry two values, scored or not, and so do a scored text with a gold value whose run-averaged score is not finite (no run with a score, or finite run scores whose average overflows) or whose covariate is missing or not finite, and a score row of a used text (a scored text with a finite gold value) without a run number or with an infinite score (see **Validity panel, broken score rows**), while a scored text without a gold value is dropped and counted as before. The panel frame gains the columns `unit` and `n_texts`; under the default `unit="text"`, on inputs whose run numbers are all present and whose input scores and any generated construct scores are finite or missing, every other value is what version 0.1.0 returned, and **Validity panel, broken score rows** says what changes on other inputs.
- **Texts as given.** A text table keeps each text as given, with only its ends stripped (`text.strip()`); version 0.1.0 collapsed every run of whitespace in it, line breaks included, to one space. The two-stage and the one-stage LLM coder send that text, so a text reaches the model with its line breaks, as in the paper's analysis code; their rule for texts under `min_chars` counts the characters of the text they send, and the text hash of a stored result is the hash of that text. `n_chars` and `n_words` still describe the text with every run of whitespace collapsed to one space, so their values, and the default covariate of the validity panel and of the corrections, do not change; the rule is `copernicus.data.table.collapse_whitespace` (also `copernicus.data.collapse_whitespace`), which the two-stage coder applies to its passages as before. A store coded by version 0.1.0 resumes, merges and feeds the hybrid coder as before for every text whose kept form equals its collapsed form, that is a text without a line break, a tab, a run of spaces or other whitespace between its words. A text whose kept form differs from its collapsed form has another prompt now, and so another hash than the stored one: a resume and the hybrid coder refuse it, and a merge refuses its id when two stores hold different hashes under it, as a store of version 0.1.0 and a store of this version do. Each message names the ids and what to do: code such texts into a new store, or pass them with their whitespace collapsed to continue the old coding.
- **Embeddings of texts as given.** The encoder embeds the text of a text table as the table keeps it (`Encoder.embed_table`, `copernicus embed texts`), with its line breaks, tabs and runs of spaces, and the hybrid coder embeds that text, not one with its whitespace collapsed, for a text under `min_words` and for a text without a verified passage; the passages of its evidence texts are as before. For a user of 0.1.0 the vectors of a text whose kept form differs from its collapsed form, and the hybrid scores of such a text where it falls back to its own text, therefore change for an encoder whose tokenizer tells whitespace apart, such as the byte-level tokenizer of `gte_qwen2_7b`. Each reference text is stripped at its ends before it is embedded (`embed_references`, `copernicus embed references`), which changes the vectors of references with whitespace at their ends only; reference sets are stored as before. The description of an embedding set made by an encoder records, from now on, `text_form` (`"as_given"`) and `texts_hash`, a SHA-256 digest over the SHA-256 digests of the embedded texts in row order; a subset leaves the digest out, and a description of 0.1.0, which holds neither key, loads as before.
- **One-stage level order.** The one-stage LLM coder lists the level descriptions of each marker in the order in which the rubric file lists the levels, as the paper's analysis code did; version 0.1.0 listed them from level 5 down to level 1 for every rubric. `Marker.level_order` holds that order (a marker built in code lists its levels in its `level_order`, by default from 5 down to 1, as before), and `Rubric.to_dict` writes each sub-rubric in it, while `Rubric.content_hash` does not see it, so the hash of every rubric stays what 0.1.0 computed and the stores and reference sets bound to a rubric stay bound to it. The extraction prompt of the two-stage coder still lists the levels from 5 down to 1 and its scoring rubric from 1 to 5. A one-stage store records the level order of every marker of every attribute (`level_orders` in its provenance) when the rubric lists the levels of some marker in another order than from 5 down to 1. For a user of 0.1.0: a one-stage store of a rubric whose file lists every marker's levels from 5 down to 1 resumes and merges as before; for a rubric file that lists the levels of some marker in another order, such as the toy rubric, which lists them from 1 to 5, the one-stage prompt has changed, and a one-stage store of version 0.1.0 is refused with a message that says so: code the texts into a new store, or list the levels of every marker from 5 down to 1 in the rubric file to continue the old coding. Two-stage stores are not affected.
- **Estimators.** The cross-fitted estimator of `repeated_study`, `ppi_crossfit`, takes the standard error of its pseudo-value column under the study's `cluster` option, with the choice that `ppi_identity` makes: by default the contributions of the texts are summed within each group whenever a group of a draw holds more than one labelled text, as in every draw of a corpus whose groups hold several texts, and `cluster=False` treats the texts as independent. Version 0.1.0 always treated them as independent. Under the default or `cluster=True`, the standard error and coverage of `ppi_crossfit` can change when groups hold several texts; neither is guaranteed to increase in a particular study. With `cluster=False`, this clustering change does not apply. With one text per group, `ppi_crossfit` keeps the standard error of 0.1.0 under the default and with `cluster=False`; with `cluster=True` its difference takes the clustered formula, as that of `ppi_identity` does. A clustered difference whose side of the corpus lies in one group, so that the side's contributions would cancel and leave its uncertainty out of the standard error, is refused on every draw that clusters, and its row is reported as `undefined_share_exceeded`: use a covariate that puts at least two groups on each side, or `cluster=False`. Before its column is cross-fitted, `ppi_crossfit` now refuses a draw as `ppi_identity` refuses it, with the same messages: fewer than two labelled texts for the mean, fewer than two labelled texts on a side for the difference (under every setting of `cluster`), and, when the draw clusters, fewer than two groups among its texts or its labelled texts; a draw that both the clustering rule and the cross-fit refuse now gives the reason of the clustering rule. Draws without two labelled texts on a side are therefore refused for the cross-fitted difference and counted in `n_undefined`, where version 0.1.0 returned the uncorrected value for that side (its cross-fitted predictions, when the side held no labelled text) or a value corrected by a single text, so a corpus whose draws often miss a side now reports that row as `undefined_share_exceeded` instead of an estimate with a large bias. The floor changes no number of a draw that holds two labelled texts on each side. The reverse calibration of `moment_subtraction`, `simex` and `oriv` refuses a score whose line on the gold values rises over the labelled texts by at most 1e-12 of the score's range there (`is_constant` applied to the line in units of the score's range, so the rule does not depend on the units of the score or of the gold values), with the message that the score does not covary with gold; 0.1.0 refused only a covariance of exactly zero, so a covariance that is zero up to rounding gave a meaningless slope from moment subtraction and SIMEX, and a refusal from ORIV that named another cause. `long_short_split` counts a text whose covariate equals the median as long (`covariate >= median`), the rule of the paper's analysis code; 0.1.0 counted it as short. The two sides are therefore the texts at or above the median and the texts below it, which ties can make unequal; a constant covariate leaves the short side empty, which the difference and the repeated study refuse. A long-minus-short difference, the `long_short_difference` rows of `repeated_study` and `corrections estimate --long-short` can therefore change when a text sits at the median of the covariate, as two texts of the toy corpus do.
- **Validity panel, broken score rows.** Under the default `unit="text"` too, a score row of a used text (a scored text with a finite gold value) without a run number stops the panel with an error that names the target and the text, on every route by which a target is built; version 0.1.0 averaged such a row into the text's score on a direct target and left it out of the generated construct, where a text whose rows all lacked a run number disappeared from the target without a count. A frame of target scores (with a `target_id` column) without a `run_number` column still counts every row as run 1, while a long attribute table without that column is refused, as in version 0.1.0, and a scored text without a gold value is dropped and counted as before, now also on the generated construct. An infinite score value of a used text stops the panel under both units and on every route, also where the generated construct would otherwise average `+inf` and `-inf` of two attributes in one run to a missing value (it now averages the finite attribute scores and keeps the infinite ones as the evidence of the refusal), and so does a used text's generated construct score that is infinite because the average of its finite attribute scores overflows. Under `unit="text"` this replaces what 0.1.0 did with such a text: it averaged the text's runs, leaving out a run whose construct score `+inf` and `-inf` had made missing, and dropped the text and counted it in `n_dropped_missing` when that average was not finite, while a text whose finite run scores overflow when averaged is still dropped and counted. Both refusals name the target, the text and, where the table has groups, its group. The infinite score is refused before the target's runs are averaged per text, and a missing run number before any metric is computed (under `unit="group"` after the checks of the groups), so that with warnings turned into errors the library's error, not numpy's warning about an average of `+inf` and `-inf`, stops the panel; under `unit="group"` too, an infinite run score is reported by this error, so within the panel the group unit's refusal of a run-averaged score that is not finite concerns a text with no run with a score or with finite run scores whose average overflows. A missing score (NaN) is admissible as before. Run numbers keep the values the frame gives them on every route: a column of pandas' nullable integer type that holds a missing value is no longer read as 64-bit floats, in which two run numbers above 2**53 could become one, so `n_runs` and the noise count every run. On inputs whose run numbers are all present and whose input scores and any generated construct scores are finite or missing, every value that version 0.1.0 returned is unchanged under the default `unit="text"`.
- **Model names behind a maker's prefix.** `capabilities_for_model` matches its prefixes (`gpt-5`, `o1`, `o3`, `o4`) against the part of the name after the last `/`, so a reasoning model named the way a router or a server names it, such as `maker/gpt-5-mini`, gets the capabilities of `gpt-5-mini`: no temperature, no `top_p`, and the `max_completion_tokens` field. The backend still sends the name as given, and an explicit `capabilities=` argument (`--backend-option capabilities=...` on the command line) still overrides the lookup. For a user of 0.1.0: such a name got the default capabilities, so `OpenAICompatibleBackend` sent a temperature and `top_p` that a reasoning model refuses; the capabilities belong to the provenance of a run and so to its identity, so a store coded by 0.1.0 under such a name does not resume or merge under this version unless the backend is given the capabilities 0.1.0 used (`capabilities=ModelCapabilities()`). - **Validity and baseline.** The validity panel with rank validity, score errors, reliability ceilings, noise, and group-clustered bootstrap intervals, and a plain-language report, which refuses a score frame whose attribute ids take the name of a generated target; the NLP-ML baseline with ridge regression on embeddings over seeds, training sizes and encoder sets, and its learning curves.
- **Corrections.** Human sampling of whole groups and sample-size planning, the planner in its own module `copernicus.corrections.planning`; cross-fitted predictions; pseudo-values; prediction-powered estimates of a mean, a group difference and regression coefficients; moment subtraction, SIMEX, instrumental-variable and repeated-study estimators; the battery that compares the corrections out of sample. A draw records the fingerprint of its table's texts and their groups (`population_hash`), and `attach_draw` refuses correction data with other texts or groups, renamed groups included, before it reads a human value, giving the counts of both tables and the drawn texts the data lack, and then a draw whose ids repeat or whose texts, groups, counts or inclusion probability do not describe its table; a draw without the fingerprint is refused as made by an earlier version. `CorrectionData.population_hash` holds the fingerprint of the data, computed once per object, and the repeated study and the battery's diagnostic draw with it instead of computing it again. `write_draw` and `read_draw`, which take a `str` or a `Path`, keep a draw in a JSON file, with the fields of `SampleDraw` as the one list both use; the description that `corrections sample` writes beside the drawn texts is such a draw file; and `read_draw` refuses a file of an earlier version (draw again) and one whose counts contradict its groups. `corrections estimate --draw` binds the coded sample to the texts file with the checks of `attach_draw`, takes `pi` from the draw and refuses a `pi` column of the gold file that differs from it; without `--draw` the command keeps `--pi-column` and the check of whole groups. The misclassification matrix's `fit` checks its training texts with the check of `applies`, the number of classes, the floor of texts per class and the informedness floor as the correction is configured, and raises `NotApplicableError` below them, also on the direct path after `applies` passed on a larger sample; latent pooling's `fit` refuses fewer than two score columns as its `applies` does; and every family's `fit` raises `NotApplicableError` with the reason of `applies` on a condition that `applies` reports, also supervised stacking's fewer than two score columns, the training texts from fewer than two groups of stacking and embedding-augmented calibration, the missing embeddings of the latter and the gold of `platt` that does not take two values. `draw_groups` computes the fingerprint of the arrays it draws from, and `draw_from_data` draws the data's own texts with the data's fingerprint.
- **Command line.** The `copernicus` command with the groups `rubric`, `code`, `store`, `references`, `embed`, `similarity`, `hybrid`, `validity`, `baseline` and `corrections`. The help tests run the same on a hosting service's runner, which forces Typer's terminal rendering, as locally.
- **Packaging.** Typed package (`py.typed`), MIT license, toy rubric, corpus and cue words for the examples and tests. The distribution is named `org-copernicus` on the package index, while the import name and the command are `copernicus`.
- **Remote code.** The one registered encoder that runs the model repository's own code is pinned to a commit; a specification or backend that allows remote code without a pinned commit, the full 40-character hash, is refused.
- **vLLM provenance.** The provenance of the vLLM backend records the engine options as canonical JSON of their values (a number stays a number, a nested option stays nested), and the backend refuses an option that is not a JSON value; the provenance, and so the run identity, changes for a run with engine options, so a store coded with engine options before this change does not match a resume after it.
- **Documentation site.** The `docs` workflow builds the site strictly (`mkdocs build --strict` on Python 3.12 with the `docs` extra) and deploys it through GitHub Pages on every push to `main` of the public repository.
